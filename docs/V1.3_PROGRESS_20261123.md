## 2. AstrBot 4.29.4 宿主契约复核

详见 `decisions/0015-v13-agent-tool-contract.md`。

- `ToolLoopAgentRunner._handle_function_tools` 内部持有 `func_tool_id`，但执行前调用 `on_tool_start(run_context, func_tool, valid_params)` 时未传 ID。
- `MainAgentHooks.on_tool_start` 分发的 `OnUsingLLMToolEvent` 仅提供 `event / tool / tool_args`。
- `FunctionToolExecutor`、本地插件 handler 调用链未转交 `func_tool_id`。
- `OnLLMResponseEvent` 在 `on_agent_done` 阶段触发，晚于工具执行。
- 插件加载器将原始 handler 包装为 `functools.partial(raw_handler, plugin_instance)`，并在 `handler_module_path` 保留来源。本插件的绑定校验已按这三个信息核验，不再直接读取 partial 的 `__module__`。

**结论**：AstrBot 4.29.4 未向执行前插件入口暴露真实 `tool_call_id`。`weave_memory_remember` 与 `weave_memory_update` 继续 fail-closed；不使用模型参数、推测关联或插件 UUID 代替宿主 ID。

### 工具面

- 工具名统一 `weave_memory_` 前缀；不重复注册 `memory_save`，不注册 Agent forget/clear。
- `weave_memory_update` 要求 `memory_id + expected_revision + content`，只更新正文，不修改 MemoryType。
- 工具由当前事件身份解析 Personal Scope；群聊、身份缺失、Consent 不满足、Scope 关闭时 fail-closed。
- handler 绑定校验仅证明当前 FunctionTool 绑定到本插件注册的 handler 实例，不宣称实现跨插件或 Persona 调用者隔离。已复核 AstrBot 4.29.4 的 `on_tool_start` 调用仍未向插件 hook 传入 `func_tool_id`；执行链的这一限制未改变。
- 本轮新增集成回归：对 `search/get/list/history` 四个只读工具分别使用另一用户事件与群聊事件调用，断言响应不含目标个人记忆正文或 ID；该测试验证插件适配层的 fail-closed 与作用域隔离，不替代真实宿主烟测。
- M2/M4 定向复核发现 `MemoryApplicationService.get_memory` 原先只校验 Scope/Consent，未过滤非 ACTIVE 状态；已在应用服务层统一将非 ACTIVE 记录映射为 `NotFound`，并增加归档记忆不可经 Agent get 读取的回归测试。

### 命令与导出

- Personal：状态、统计、操作记录、JSON/Markdown 导出；删除、清空、关闭二次确认。
- Group：新增 `/织忆 群导出 [json|md]`，只导出当前群 ACTIVE 记忆，必须通过群管理员决策；普通成员拒绝。序列化复用 `app/export.py`。
- 群管理员能力继续走既有群命令与群服务，不开放 Agent Group 工具。

### 检索诊断

- Personal 与 Group 检索均写入 `recall_diagnostics/recall-YYYY-MM-DD.jsonl`，每请求一行。
- 包含 `trace_id`、时间、identity/scope 摘要、query SHA-256、候选 ID/BM25 排名与分数/过滤原因、最终返回或注入 ID、Token 估算及预算裁剪原因。
- 默认不记录查询原文或记忆正文；identity 的 tenant/subject 使用哈希摘要；默认保留 7 天，可配置。
- 查询原文只有显式 opt-in 才记录，并对常见邮箱、手机号、长数字串做模式脱敏；脱敏不保证识别所有个人信息。
- 本轮补齐了 Agent 搜索工具和 `/织忆 查询` 的最终返回 ID 与 Token 估算记录；先完成访问记录，再写诊断，避免日志把已返回结果记成空注入集合。
- 诊断写入失败只告警，不阻断检索或聊天；诊断不改变召回顺序或访问时间。
