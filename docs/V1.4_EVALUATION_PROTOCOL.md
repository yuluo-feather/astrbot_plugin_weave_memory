# V1.4「验线」评测协议与实施记录

**依据**：`星羽塔罗_织忆_V1.4_验线_计划书.md` V1.2（2026-11-23）。
**当前阶段**：M0 评测口径冻结、M1 Golden Set 与 Harness 初版已实现；Golden Set 为合成标注草稿，人工标注复核待完成；V1.4 尚未完成退出验收。
**运行时约束**：不修改检索/注入语义、运行时默认参数或 `_conf_schema.json`；评测只使用临时 SQLite 数据库与合成夹具。

## 1. 数据集

- 文件：`eval/v1.4/datasets/golden_v1.json`，版本 `1.0.0`。
- 50 条查询，Personal 25 条、Group 25 条。
- 类别：精确事实 10、偏好 10、近期主题 10、跨作用域 5、已删除/过期 5、无记忆 10。
- 固定留出集 10 条（20%），每类至少有一条留出样本；参数实验仅允许 `train` split。
- 每条样本包含 query、scope 身份字段与 scope_id、subject_id、期望记忆 ID/内容、干扰/排除 ID、category、source_type、memory_type、有效期、created_at、caller、dataset_version、labeler、split。
- 数据仅为合成文本；严禁将生产记忆或生产对话正文复制进仓库。当前标签由助手生成初稿（`assistant-generated-draft`），尚未完成计划书要求的人工标注复核，不计作 Golden Set 最终验收完成。

## 2. Harness

入口：`python scripts/evaluate_v14.py`。

- 在临时目录构建合成 SQLite 数据库，使用项目真实 `SQLiteMemoryStore`、`SQLiteFTSIndex`、`RecallService`、`GroupRecallService` 和 Context Composer；退出时关闭并删除临时库。
- 固定评测时间 `2026-11-23T12:00:00+00:00` 与随机种子 `1401`。
- Personal candidate K=12、inject K=4、token budget=384；Group candidate K=8、inject K=2、token budget=192。
- 延迟每条样本 warmup 2 次、重复 30 次，测量进程内 Recall 调用，不含 Provider 网络；报告 P50/P95。
- 输出 `eval/v1.4/reports/baseline_v1.json` 与 `.md`，包含数据集 SHA-256、参数、环境元数据、逐样本实际/期望结果、分类与 Scope 汇总。
- 可使用 `--split train` 和显式参数覆盖进行训练集实验；只要提供任何参数覆盖，`--split` 必须是 `train`。`holdout` 不允许参与参数选择。

## 3. 指标定义

- Recall@K / Precision@K / MRR：非空期望集按计划书定义计算；Precision@K 的分母固定为 K（即使实际返回不足 K 条也不缩小分母）；非空期望集未命中时 MRR=0。
- 空期望集（`no_memory`、`expired_deleted`）的 Recall@K、Precision@K、MRR 记 N/A，不进入非空均值。Cross-scope 样本包含当前 Scope 的期望记忆和另一 Scope 的同词干扰记忆，参与常规指标并单独统计 foreign distractor 命中。无记忆正确率仅对 `no_memory` 与 `expired_deleted` 两类计算。
- 无记忆正确率：`no_memory` 与 `expired_deleted` 样本中，候选结果为空的比例。
- 注入有效性：0=无关、1=部分相关、2=直接帮助；至少 20% 样本双人评分，不一致由第三人裁定。评分模板：`eval/v1.4/datasets/injection_rubric_template.csv`。当前未人工评分，报告必须标记 pending。
- 平均 Token：使用项目 `estimate_tokens`，统计 Composer 返回上下文（包含前缀/后缀）；没有注入上下文的查询按 0 计入全样本平均。
- 检索延迟：按每样本 2 次 warmup、30 次测量，报告每个 Scope 的 P50/P95。
- 错误归属率：实际候选中 Scope/subject 与样本目标不一致的数量 / 实际候选总数；无候选时记 0，并同时报告分子分母。
- 过期/删除召回率：应排除的 ID 被候选召回数 / 所有 `excluded_memory_ids` 数；预期为 0。

## 5. 当前基线的初步观察

基线运行使用 `150ee46` 运行时代码，报告为 `baseline_v1`：

- Personal 与 Group 非空正样本的 candidate Recall@K、MRR 均为 1.0；注入 Recall@K、MRR 均为 1.0。
- Precision@K 使用固定 K 分母；实际数值以 `baseline_v1.md` 报告为准。近期主题类 Precision 较低，提示当前 OR 召回在主题词较泛时产生较多候选干扰。该观察是评测结果，不授权本版调参或改检索语义。
- 无记忆正确率为 1.0；跨 Scope 干扰命中为 0；过期/删除召回率为 0；错误归属率为 0。
- 延迟数据仅代表当前 Python/SQLite 环境中的临时库与合成数据，不作为生产环境性能承诺。
- 注入有效性尚未完成人工 Rubric 评分，不得从 Recall/Precision 推断人工帮助程度。


### 5.1 首轮失败样本分析（按固定骨架）

- **Query**：`最近整理 插件 并发故障注入`（样本 `P-RT-01`）。
- **期望**：`p-rec-1`（“用户最近在整理插件的并发故障注入测试”）。
- **实际**：`p-rec-1` 排名第一，同时返回 `p-rec-5`、`p-rec-4`、`p-rec-2`、`p-rec-3`。
- **原因分类**：共享词导致的 OR 扩散。当前 FTS 查询由多个词项 OR 组合，“最近/整理”等共现词使同一 Scope 的其他近期主题也进入候选；相关项仍排第一，因此 Recall/MRR 高，但 Precision@K 低。
- **建议**：在 V2.0 评估中比较候选词项权重、短语约束及语义重排的增益，并使用留出集验证；V1.4 不修改当前运行时排序或默认参数。

同类现象也出现在群组精确事实查询（如 `本群例会 周三 15:00`），表明共享上下文词可能扩大候选集合。报告 JSON 保留每条样本的完整候选 ID，便于进一步抽查。


## 6. V1.5 / V2 决策输入（暂定）

- 当前 50 条合成样本没有出现正样本漏召回，不能据此认定 FTS 存在覆盖率缺口；该结论仍受样本规模和待人工复核标注限制。
- 主要可见问题是候选精度：多个查询词按 OR 组合后，共享词会扩散到同 Scope 的其他记忆；近期主题最明显，部分群组事实也有类似现象。
- V2.0 可把近期主题、宽泛查询列为词项权重/短语约束/语义重排的重点消融场景，但必须在人工复核 Golden Set 与固定留出集上验证；本结果不构成现在引入 Vector/Rerank 的授权。
- Cross-scope、无记忆、过期/删除样本本轮均未出现越界或误召回；这些安全边界应在后续检索实验中作为不可退化项。
