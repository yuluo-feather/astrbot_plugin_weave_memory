# V0.4 写协调与生命周期实现报告

日期：2026-11-22
状态：实现完成，待阶段验收

## 实现内容

- `WriteCoordinator`：单事件循环单实例 `asyncio.Lock` 串行化创建、更新、删除、清空和关闭操作。
- `LifecycleService`：唯一应用层状态转换入口；候选激活、SUPERSEDED 恢复权限守卫；到期处理。
- SQLite migration v2：Scope `is_enabled` / `disabled_at`。
- 删除：同一事务写入最小 `DELETED` tombstone audit，标记 FTS dirty，物理删除正文、Revision、Source、Tag。
- 清空：仅作用于指定 Personal Scope；逐条 tombstone + scope 汇总审计 + 同事务物理清理。
- 关闭 Scope：停写、停普通读取和检索，不删除正文；管理审计保留。
- Delete/Clear/Disable 使用 operation ID；相同操作重放幂等，不同操作复用 ID 冲突。
- 启动恢复：检查 schema 版本、FTS integrity、dirty 状态；必要时重建或重建 FTS 表后回填。
- V0 没有注入缓存和后台任务队列，因此未创建空缓存/任务子系统。

## 故障与并发验证

- 并发相同去重键写入只有一个成功，另一个明确 Conflict。
- 乐观锁阻止旧 revision 覆盖。
- 删除审计冲突导致事务回滚，正文保持完整。
- 删除/清空提交后索引失败，正文删除仍保持权威；检索 fail-closed，启动恢复可修复索引。
- 关闭后普通读取/检索/写入不可用，底层正文仍保留。
- 状态变化必须经过 LifecycleService；DELETED 必须走不可逆物理清理路径。
