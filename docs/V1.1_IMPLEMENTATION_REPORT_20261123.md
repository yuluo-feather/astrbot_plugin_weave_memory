## 1. 实现内容

### Core / Ports

- `ScopeType.GROUP` 允许构造；`Identity` 校验 GROUP/GROUP 六元组；PERSONAL/USER 与 GROUP/GROUP 分离。
- 新增 `AdminSource`、`AdminDecision`；`GroupConsentRevocationPending`。
- 新增 `AdminResolver`、`GroupScopeStore` 端口；`SearchIndex.search` 增加 `scope_type` 防御过滤（默认 PERSONAL）。

### SQLite v5

- `005_group_scopes.sql` 重建 `memory_scopes`：允许 PERSONAL/GROUP、USER/GROUP，新增 `admin_ids_json`、`admin_source`。
- `CURRENT_SCHEMA_VERSION=5`；v4→v5 迁移在 FK-off 事务内完成；迁移前/销毁前使用 SQLite backup API。
- `rollback_to_v10()`：有 GROUP Scope/群记忆/群 consent 时拒绝；无群数据时重建 v4 表并回到 v4。
- 群 Scope 默认 disabled（`create_scope` 为 GROUP 写 `is_enabled=0`）。
- 群存储：admin 元数据、enable/disable（GROUP_ENABLE/GROUP_DISABLE）、ACTIVE 计数、群备份校验、FK 安全 `delete_group_scope`（记忆/关联 → consent → operations → scope + FTS dirty + purge pending）。

### App

- `GroupScopeService`：六元组 UUID5、管理员解析、ensure/status/enabled。
- `GroupLifecycleService`：enable/disable/clear/destroy；enable 先 enable 再 grant（disabled Scope 不能 grant）；destroy 要求先关闭、自动备份+sidecar、提交后 FTS 重建+purge。
- `GroupMemoryService`：管理员 MANUAL+ADMIN 写入；topic→FACT、agreement/atmosphere→PREFERENCE、experience→EVENT；成员写入拒绝；列表/查询要求 enabled + group_memory granted；`group_max_active` 软上限告警。
- `GroupRecallService` / `GroupContextComposer`：当前群、`scope_type=GROUP`、群独立预算（默认 192/2/8）、不可信文本转义。
- `WriteCoordinator.run_serialized` 支持群销毁多步同步事务。

### AstrBot Adapter / 配置

- 群身份解析（platform + tenant_id + GROUP + group_id + GROUP + group_id）。
- `AstrBotGroupAdminResolver`：平台群主/管理员优先，`is_admin()` 次之，`group_admin_ids` 配置回退，全部缺失 fail-closed。
- 群命令：`群帮助/群开启/群关闭/群保存/群列表/群查询/群状态/群清空/群销毁`，群聊 only；个人命令仍私聊 only。
- 群注入 Hook：群事件只注入当前群，个人/群双向隔离；临时 TextPart。
- `_conf_schema.json`：`group_admin_ids`（`platform|tenant_id|group_id` → admin ids）、群预算、`group_max_active`；构建脚本已包含该文件。
