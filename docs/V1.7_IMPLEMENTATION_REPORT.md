# V1.7「接线」实现报告（2026-11-23）

状态：核心实现完成；真实宿主导入/导出烟测待补。

## 变更

- 契约：新增 ADR-0017，并同步 `CONTRACTS` §15、`DATA_MODEL` §17、`SECURITY` §14、`ARCHITECTURE` §12、`TEST_PLAN` §19。
- Schema v8：`008_import_jobs.sql` 新建 `import_jobs`，为 `memory_sources.evidence_ref` 建索引；`SQLiteDatabase.CURRENT_SCHEMA_VERSION=8`，新增 `rollback_to_v7`（`import_jobs` 非空时拒绝）；`rollback_to_v05/v5/v6` 按链逐级回滚；链式回滚在改动前统一预检守卫，守卫失败保持原版本。
- 导出 v2：`app/export.py` 改为 `weave-memory-export-v2`，文件级 `export_id` / `source_platform` / `exported_at` / `schema_version`，条目级 `source_memory_id` / `source_revision` / 有效期 / `body_omitted`；默认只导 ACTIVE，`all` 额外导出 ARCHIVED/EXPIRED/SUPERSEDED 元数据且不含正文。
- 导入服务：新增 `app/import_service.py`，解析/校验、作用域类型强制、四元组幂等、内容去重、状态映射、审计、dry-run、逐条回报、任务续跑与回滚；`WriteCoordinator.create_import` 在同一协调锁内查重并插入。
- 导入任务：新增 `core.model.ImportJob` / `ImportJobStatus`、`core.ports.ImportJobStore`、`adapters/sqlite/import_jobs.py`；任务绑定 `scope_id` / `subject_id`，续跑与回滚强制同一作用域。
- 命令：`/织忆 导入 [dry-run]`、`/织忆 导入 回滚 <任务ID>`、`/织忆 群导入 [dry-run]`、`/织忆 群导入 回滚 <任务ID>`；`/织忆 导出` 与 `/织忆 群导出` 支持 `all`；帮助与 metadata 同步。
- 附件适配器：新增 `adapters/astrbot/attachments.py`，从消息 File 组件读取 JSON，限制 5 MiB / UTF-8 / 只解析不执行，不直接依赖宿主 SDK 类型。
- 管理 API：新增 `GET /v1/export` 与 `POST /v1/import`，只支持群作用域；要求非空 `api_admin_usernames` 且用户名命中（fail-closed），群 enabled + GRANTED；个人 scope 一律拒绝。
- 配置：本版不新增配置项；导入上限为常量。

## 限制

- 未在真实 AstrBot 宿主执行导入/导出烟测；消息 File 组件读取按宿主 `File.get_file()` 契约实现，仍需真机确认不同平台适配器的附件行为。
- 断点续跑需要用户重新发送同一文件；不提供后台自动续跑。
- V1.2 的 v1 导出文件不含幂等四元组，按计划书要求拒绝导入；需先重新导出为 v2。
- 管理 API 的 `POST /v1/import` 是 V1.6 只读边界外的唯一写端点，仅群作用域且要求显式管理员白名单；个人导入仍只走命令。
- 导入只创建新记忆、不更新既有记忆；冲突跳过或记冲突，不自动确认候选。
- 完整备份恢复、向量检索与 WebUI 仍分别留给 V1.8/V2.0/V2.1。
