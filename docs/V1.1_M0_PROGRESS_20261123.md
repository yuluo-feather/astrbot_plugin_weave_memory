## 3. M0 冻结的关键决定

- 身份：`platform + tenant_id + GROUP + group_id + GROUP + group_id`；`scope_id` 用完整 Identity UUID5，格式与 Personal 一致。
- 管理员：`admin_source=PLATFORM_ROLE/EXPLICIT_CONFIG/NONE`；平台角色优先、配置回退、无来源 fail-closed；每命令重新解析 sender；不接受 `admin_id`；`group_admin_ids` 按 `platform + tenant_id + group_id` 隔离（配置为对象映射，也接受对象数组）。
- `admin_ids_json`：`PLATFORM_ROLE` 下是审计快照，不用于授权；`EXPLICIT_CONFIG` 下镜像配置；`NONE` 为空。
- 群 consent：`group_memory` 默认拒绝；开启授予、关闭撤销且可逆、清空不改 consent；个人关闭仍永久。
- 群写入：仅管理员命令；`MANUAL + ADMIN`；成员拒绝；topic→FACT，agreement/atmosphere→PREFERENCE，experience→EVENT；metadata 固定键。
- 群入口：群事件 Adapter/命令/注入；独立预算 `192/2/8`；`scope_type=GROUP` 防御过滤；群/私双向隔离。
- v5：`memory_scopes` 重建，允许 GROUP/GROUP，加 admin 列；迁移前备份；有群数据拒绝 `rollback_to_v10`；无群数据可回滚并再次迁移；V1.0 不能直接打开 v5。
- 群关闭（is_enabled=0）不等于 schema 回滚；v5 库、群数据与 admin 列保留。
- V1.1 无导出；导出/完整保留期/自动清理在 V1.2。群增长 `group_max_active=200` 告警。

## 4. P2 处理

- `group_admin_ids` 按平台实例+群隔离，已写入 ADR-0009。
- 群关闭后可执行 `群清空`；consent/enabled 状态不变；重新开启复用 Scope 并追加新 GRANT，已写入 ADR-0010。
- v5 回滚运维步骤：先备份；保留群数据则留在 v5；必须回 V1.0 则 `群关闭 → 群清空 → 群销毁` 或 `群关闭 → 群销毁`，再 `rollback_to_v10`，已写入 ADR-0011。
- 群解散最小行为、保留默认、增长告警、`群状态` 不泄漏管理员列表，已写入 LIFECYCLE/SECURITY。
- FTS/读取 `scope_type=GROUP` 防御过滤，已写入 DATA_MODEL/CONTRACTS/TEST_PLAN。

## 5. M0 复审修订（V1.3/V1.4）

- 新增 `群销毁 确认`：仅管理员、必须先关闭、必须确认；服务内自动生成并校验备份 + sidecar manifest；删除顺序（单事务）为群记忆/关联 → consent 历史 → operations 审计 → scope；事务内标记 FTS dirty 与 `secure_purge_pending`，提交后先重建 FTS 再 purge；不可恢复；用于 v5→v4 回滚前置。
- 读取矩阵：`群列表/查询` 仅 `enabled + group_memory=GRANTED`；`群状态` 可 disabled 读，但不返回正文/管理员列表；无 Scope 返回 `created=false`；`count` 只统计 ACTIVE。
- `GroupScopeService` 只负责 Scope/管理员/状态；`GroupLifecycleService` 负责 enable/disable/clear/destroy/consent；补 core 端口/返回类型。
- 补 `experience -> EVENT`、`group_admin_ids` 对象数组格式、`GROUP_ENABLE/GROUP_DISABLE/GROUP_DESTROY` operation ID/幂等/失败顺序。
- 回滚测试只保留 `群关闭→群清空→群销毁→rollback` 与 `群关闭→群销毁→rollback`；`群开启→群清空→群销毁` 被拒绝；补备份校验/子表 FK/事务回滚测试。
