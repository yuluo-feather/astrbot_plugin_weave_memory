# V1.6「候线」实现报告（2026-11-23）

状态：核心实现完成，未做真实宿主 API 烟测；WebUI 按计划留 V2.1。

## 变更

- 契约：新增 ADR-0016，并同步 `CONTRACTS` §14、`DATA_MODEL` §16、`LIFECYCLE` §10、`SECURITY` §13、`ARCHITECTURE` §11、`TEST_PLAN` §18。
- Schema v7：`007_candidate_expiry.sql` 新增 `memories.candidate_expires_at` 与索引，回填既有候选为 `created_at + 7 天`；`SQLiteDatabase.CURRENT_SCHEMA_VERSION=7`，新增 `rollback_to_v6`（有候选时拒绝）；`rollback_to_v5` / `rollback_to_v10` / `rollback_to_v05` 按版本链逐级回滚。
- 候选 TTL：`candidate_ttl_days`（默认 7）创建时写入；读取候选列表时惰性归档到 `ARCHIVED`，写 `CANDIDATE_EXPIRE`；确认/拒绝写 `CANDIDATE_CONFIRM` / `CANDIDATE_REJECT`。
- 拒绝策略：`rejected_keep_body` 默认 false，同一事务物理清理正文/版本/来源/标签/关系与 memories 行，只保留不含正文的 operation 审计；开启时保留 `REJECTED` 行与正文。
- 管理 API：新增 `app/management_service.py` 与 `adapters/astrbot/web_api.py`，注册 9 个只读端点（overview/candidates/memories/detail/history/groups/retrieval debug/settings/maintenance）；按 dashboard 用户名与 `api_admin_usernames` 鉴权；群作用域要求 enabled + `group_memory=GRANTED`；个人 scope 一律拒绝；调试不返回正文、不更新访问时间、不写诊断。
- CLI：`weave_admin.py` 新增 `candidates`、`expire-candidates`、`maintenance-status`；`groups/rollback-preview/group-destroy/cleanup-backups` 保持。
- 配置：`_conf_schema.json` 新增 `candidate_ttl_days`、`rejected_keep_body`、`api_admin_usernames`。
- 共享预算选择：个人/群 Composer 与检索调试复用 `select_with_budget`，行为与原有逐条预算一致。

## 限制

- 未在真实 AstrBot dashboard 中调用管理 API；路由名称与参数按宿主 `register_web_api` 契约和既有插件实现核对，仍建议真实宿主冒烟。

- 个人正文与候选确认/拒绝仍只走用户命令；管理 API 不提供写端点。
