# 织忆 V0.5 真实 AstrBot 宿主烟测（2026-11-23）

> 本报告保留宿主验证事实与限制；为避免把真实用户标识、记忆正文和本机目录带入开发交付包，测试数据已概括化。原始运行日志不随工作区分发。

环境：AstrBot v4.29.4，Windows 本地实例，WebChat。插件数据目录为 AstrBot 插件数据目录下的 `astrbot_plugin_weave_memory/weave_memory.sqlite3`。

安装注意：测试实例的 `plugin_set` 是手工白名单；必须包含 `astrbot_plugin_weave_memory`，否则插件能加载但命令可能被过滤。本轮已加入并保留。

自动化复核：V0.5 基线 `python -m pytest -q` → 69 passed（Python 3.12.10）；`compileall` 通过。

## 前置修复

本轮修复了两处导致插件无法加载的 P0：

1. `from astrbot.api.agents import TextPart` 改为 `from astrbot.core.agent.message import TextPart`。
2. 插件内包绝对导入改为相对导入（`.core...`），并在测试中按真实插件包布局加载。

同时修复了 Consent append-only 的排序问题：按 SQLite append 顺序取最后一条事件，避免同一微秒内“撤销后重新授权”仍被判为 REVOKED。

## 加载与烟测结果

宿主日志记录了插件首次加载及多次重载成功。测试流程及结果：

| # | 操作 | 结果 |
|---|---|---|
| 1 | 用户 A 授权个人记忆 | 命令成功返回授权结果 |
| 2 | 用户 A 显式保存个人记忆 | 保存成功，FTS 索引同步 |
| 3 | 新会话询问已保存事实 | 模型回答与已保存记忆一致，证明本轮上下文注入生效 |
| 4 | 第二测试用户使用独立 WebChat 会话 | 只能读取自己的 Scope，无法读取用户 A 的记忆 |
| 5 | 用户 A 撤销授权后查询/新会话提问 | 普通列表/检索被拒绝；新会话不再注入用户 A 的记忆 |
| 6 | 重新授权并重载插件 | 历史数据保留；重载后列表与主动查询正常 |
| 7 | 删除记忆并模拟 FTS dirty 状态 | 删除生效；索引脏时聊天仍正常响应，记忆注入降级；索引恢复后查询恢复 |

为隔离其他记忆插件对模型回答的影响，干净隔离测试期间临时收窄 `plugin_set`；测试结束后已恢复原设置，并保留目标插件启用。
