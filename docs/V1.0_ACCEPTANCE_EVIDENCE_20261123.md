## 2. 临时 TextPart 的对象级持久化证据

在 AstrBot 宿主 venv 中构造：

```python
temp = TextPart(text="TEMP-PART-CANARY-7f3a").mark_as_temp()
message = Message(role="user", content=[TextPart(text="normal-context"), temp])
dumped = dump_messages_with_checkpoints([message])
```

实际输出：

```text
temp_part_no_save True
normal_present_in_dump True
canary_absent_from_dump True
message_no_save False
```

结合 AstrBot 源码契约：

- `TextPart.mark_as_temp()` 设置 `_no_save=True`，docstring 写明 “provider-facing only, not persisted”。
- `ProviderRequest` 通过 `model_dump_for_context()` 把 `_no_save` 保留在请求内容块中。
- `internal.py:_save_to_history` 跳过 `_no_save` 的 user/assistant 消息；`dump_messages_with_checkpoints` 在持久化 dump 时过滤 `_no_save` 内容块。
- Provider 适配器在发送给模型前删除 `_no_save` 字段，该标记只影响持久化。

结论：临时记忆上下文会进入当前 Provider 请求，但从持久化消息 dump 中排除；普通用户消息内容仍保留。该证据是对象级 + 目标版本源码契约，不等同于对具体 Provider 网络请求的 token 级抓包。
