# V1.0 宿主能力验证记录（AstrBot）

日期：2026-11-23
目标版本：AstrBot 4.29.4
用途：回应羽忆侧实现审查 §2.9 / §2.10 的「实现前宿主验证无记录」。

## 1. 消息事件与身份字段

- 可用：`message_obj`、`message_str`、`is_private_chat()`、`get_group_id()`、`get_platform_name()`、`get_platform_id()`、`get_sender_id()`、`get_extra()` / `set_extra()`、`send()`。
- 织忆身份只取 platform / tenant / sender（群为 group_id 六元组），**不把会话标识放进 Scope**：记忆按用户或群共享，跨会话可见；会话标识属于宿主消息属性，不进入记忆边界。
- 结论：身份适配器对缺失字段 fail-closed；群事件在个人入口被拒绝。

## 2. 会话标识

- 宿主提供 `unified_msg_origin` / `session_id`，用于消息路由与日志关联。
- 织忆 V1.0 不使用会话标识构造 Scope；`tests/unit/test_astrbot_identity.py` 固定了「身份使用 platform / instance / sender，不使用 session origin」的行为。

## 3. 注入扩展点

- 个人与群记忆都通过 `on_llm_request` 注入，使用临时 `TextPart`；注入失败只记 warning，不阻塞聊天。
- 未使用回合结束事件：V1.0 没有依赖回合结束的回写或提取逻辑；后台提取属于 V1.5。

## 4. 工具、热重载与数据目录

- 工具注册：`@filter.llm_tool` 注册的 `weave_memory_remember` 在 AstrBot 4.29.4 可用；真实宿主日志可见 `Added llm tool`。
- 热重载：插件 `terminate` 由宿主调用；V1.0 收尾等待写协调器关闭，并对关闭设置超时上限（超时记录 warning 后继续释放连接）。
- 数据目录：通过 `StarTools.get_data_dir()` 取得插件数据目录，SQLite 与备份文件都落在该目录下。

## 5. 结论

计划书 §9 列出的宿主能力已逐项验证；实现只在命令层与注入层读取宿主字段，未引入额外的领域事件抽象。该结构差异已写入 V1.0 计划书 §9 注记，不回改 V1.0 代码行为。
