# ADR-0015：V1.5 自动提取的分层授权与任务管线

状态：Accepted for V1.5（M0 契约冻结；M1 核心已实现，默认关闭；宿主烟测与质量采集待补）
日期：2026-11-23
依据：`星羽塔罗_织忆_V1.5_添线_计划书.md` V1.5；ADR-0012（默认登记）；ADR-0014（schema v6）

## 背景

V1.2 的 `auto_enroll` 只建立 `personal_memory=GRANTED`，不能推导出允许捕获私聊、自动提取、外部模型处理或保存候选。V1.5 需要把这四项能力分开授权，并把“捕获—窗口—模型—候选”的顺序固定为安全闸门。

计划书 §4.0 有一处措辞冲突：既写“拒绝任一授权只影响对应能力”，又写“`external_model=false` 时关闭自动提取”。本 ADR 冻结实现口径，消除歧义；计划书修订记录同步记录。

## 决策

### 1. 授权记录

在 `memory_consents` 新增以下 `consent_type`，全部 append-only，按 `(subject_id, scope_id, consent_type)` 取最后一条事件为准，不 UPDATE 历史行：

| consent_type | 含义 | 默认 |
|---|---|---|
| `extraction_capture` | 允许捕获本人私聊消息 | 无记录即拒绝 |
| `extraction_auto_extract` | 允许自动提取候选 | 无记录即拒绝 |
| `extraction_external_model` | 允许把必要文本发送给外部 LLM | 无记录即拒绝 |
| `extraction_store_candidate` | 允许保存候选与来源 | 无记录即拒绝 |
| `extraction_sensitive_categories` | 允许进入候选的敏感类别白名单 | 空 |

- `extraction_sensitive_categories` 的 `metadata_json.categories` 保存类别列表；空列表表示不保存任何敏感类别。
- `auto_enroll` 只写 `personal_memory`，绝不写以上任何一项，也不改写已有事件。
- 授权命令只对本人私聊生效；群聊一律拒绝。

### 2. 有效条件

以下是“有效执行条件”，不是新的 consent 事件。拒绝某一能力不会改写其他能力的 consent 记录。

| 动作 | 必须同时满足 |
|---|---|
| 捕获消息 | 事件为私聊 + `personal_memory=GRANTED` + scope `is_enabled=1` + `extraction_capture=GRANTED` + 全局 `extraction.enabled=true` |
| 自动提取 | 捕获条件 + `extraction_auto_extract=GRANTED` + `extraction_external_model=GRANTED` |
| 保存候选 | 自动提取条件 + `extraction_store_candidate=GRANTED` |
| 敏感类别入候选 | 保存候选条件 + 类别在 `extraction_sensitive_categories` 白名单内 |

- **`external_model` 未授予时，`auto_extract` 不执行**，不做本地模型兜底，不静默外发。`auto_extract` 的 consent 记录保持原状，只是有效条件不满足。
- 全局 `extraction.enabled=false` 时，以上全部不执行，已有候选与历史不受影响。
- `提取 开启` 不重开已关闭 scope；scope 关闭时返回明确错误，提示先恢复 scope（`/织忆 授权` 或相应开启命令）。`提取 开启` 本身不改变 scope enabled。
- `提取 开启 全部` 是便捷入口：逐项追加四项 GRANTED 事件；部分失败时明确报告已授予项与失败项，不宣称全部成功。

### 3. 捕获与窗口

- 只处理 `scope_type=personal` 的私聊事件；群聊、群共享、Group personal 一律不捕获。
- 顺序铁律：身份解析 → scope 查找/启用检查 → `personal_memory` 与 `extraction_*` 授权 → 敏感预过滤 → 会话窗口整理 → `LlmExtractor`。未通过前不得进入窗口或模型。
- 窗口默认只含用户消息；Assistant 回复与工具输出默认排除，需配置显式开启并记录来源。
- 窗口仅保存在任务处理的内存中；完整对话原文不长期保存。

### 4. 敏感信息前置过滤

- 在进入窗口与 `LlmExtractor` 之前执行；不能等模型输出后再判断。
- 默认类别：凭据/密码/令牌/API key、身份证件号、银行卡号、精确住址。
- 无法可靠识别但疑似敏感的内容：默认不送外部模型；可本地丢弃或按白名单人工确认。
- 敏感类别进入候选必须同时满足 `sensitive_categories` 白名单。
- 过滤器不记录正文到运行日志；Sensitive Leakage Rate 是安全验收项，目标为 0。

### 5. 任务模型

`extraction_jobs`（schema v6）至少包含：

- `id`、`platform`、`tenant_id`、`scope_id`、`subject_id`
- `conversation_id`、`watermark`、`content_hash`
- `status`、`attempts`、`last_error`
- `created_at`、`updated_at`、`metadata_json`

状态：`PENDING / RUNNING / SUCCEEDED / SKIPPED_DUPLICATE_ACTIVE / FAILED / CANCELLED`。

- 幂等键：`(platform, tenant_id, scope_id, conversation_id, watermark, content_hash)`，唯一约束；重复提交不重复写入。
- 队列有界；积压可见；有限重试；失败记录类型化错误，不阻塞聊天。
- 启动恢复未完成任务；热重载停止接收新任务 → 等待/取消 → 保存状态。
- 任务状态与计数可通过 `/织忆 提取 状态` 查看；不返回正文。

### 6. 候选规则

- 来源固定 `SourceType.INFERRED`，状态 `CANDIDATE`，不得自动升级为 `ACTIVE`。
- 类型限 `PREFERENCE / FACT / EVENT`；正文、主体、来源引用、可选置信度经 Schema 校验。
- 同键已有 `ACTIVE`：不创建候选，任务记 `SKIPPED_DUPLICATE_ACTIVE`，可在状态中看到。
- 同键已有 `CANDIDATE`：幂等更新候选内容与来源，不新增行。
- 显式保存 / AGENT 工具写入撞到同键 `CANDIDATE`：返回 `Conflict`，要求先确认或拒绝候选；不静默替换。
- 确认：依赖 `ACTIVE`/`CANDIDATE` 互斥唯一索引；候选被更新/删除时按 `expected_revision` 返回 `Conflict`。
- 拒绝：记录原因，不进入检索、不参与注入。
- 候选不参与正常检索/注入；确认后才进入 FTS。
- 候选过期转 `ARCHIVED`，不物理删除；TTL 与批量清理在 V1.6。
- 候选确认/拒绝仅用户命令，不注册 Agent 工具；批量/管理 API 在 V1.6。

### 7. 端口与边界

- `LlmExtractor`：平台无关模型端口，输入受限窗口与允许类别，输出结构化候选或 `None`；实现位于 Adapter，不进入 `core`。
- `ExtractionService`：应用服务，负责有效条件、任务幂等、候选写入、失败隔离与恢复；不直接依赖 AstrBot/SQLite。
- `core` 不调用 LLM、不读取宿主事件对象；`adapters/astrbot` 只做事件捕获与命令翻译。
- 模型调用失败、超时或输出不合法：任务失败/重试，聊天继续；不得把异常传播为聊天失败。

### 8. Schema 与回滚

- schema v6，迁移 `006_extraction_jobs.sql`；其余表不改。
- 迁移前自动备份并校验；失败中止迁移。
- v6→v5 回滚守卫：`extraction_jobs` 为空，或保留表停用、不删除数据；回滚后关闭全部提取行为。
- V1.5 不改变显式写入、检索、注入与群路径语义。

## 未决项（需主人决定，不阻塞 M0）

1. 用户显式“记住 X”撞到同键候选时，计划书要求返回 `Conflict`。审查意见认为机器猜测不应阻塞用户明确陈述；当前按计划书保留 `Conflict`，是否改为“显式写入优先并归档候选”留待 V1.5 实现前决定。
2. 同键已有 ACTIVE 时自动提取记 `SKIPPED_DUPLICATE_ACTIVE`，只做可见计数；用户改变后的偏好能否通过候选进入，仍按计划书不在 V1.5 解决。
3. 过期候选 TTL、物理清理与批量管理在 V1.6。
4. 候选确认/拒绝的 Agent 工具在 V1.6；V1.5 仅用户命令。

## 后果

- V1.2 默认登记与 V1.3 工具写入语义不变；V1.5 新增能力默认关闭。
- `external_model` 未授予时自动提取不执行，避免“无本地模型却静默外发”的歧义。
- 计划书 §4.0 的措辞在修订记录 V1.6 中按本 ADR 澄清；其余范围不变。
- 新增 schema v6、consent 类型、命令面、任务表与候选路径，均需在 V1.5 实现与测试中落地。
