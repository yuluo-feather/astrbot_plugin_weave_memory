# ADR-0016：V1.6 候选 TTL 与只读管理 API

状态：Accepted（V1.6 实现契约）
日期：2026-11-23

## 背景

V1.5 已能产出 `CANDIDATE`，但候选没有 workflow 过期时间，也缺少管理面。V1.6 计划书要求：

- 候选按 `candidate_expires_at` + `candidate_ttl_days`（默认 7 天）惰性过期，转 `ARCHIVED`，不物理删除；
- 候选确认/拒绝/过期写 `CANDIDATE_CONFIRM` / `CANDIDATE_REJECT` / `CANDIDATE_EXPIRE` 审计；
- 拒绝默认清除正文，只保留审计元数据；`rejected_keep_body` 默认 false；
- 通过宿主 `Context.register_web_api` 注册只读管理 JSON API，按端点分权；
- 个人正文不经 API，检索调试只记 ID/摘要。

ADR-0014 已冻结 schema v7（`007_candidate_expiry.sql`，`memories.candidate_expires_at`）。

## 决策

### Schema v7

- 迁移 `007_candidate_expiry.sql` 只给 `memories` 增加 `candidate_expires_at TEXT`，并补 `(status, candidate_expires_at)` 索引。
- 迁移把既有 `status='CANDIDATE'` 的行回填为 `created_at + 7 天`（迁移时不知道配置，固定使用默认值 7；迁移后新候选按运行时配置写入）。
- `MemoryEntity` 新增 `candidate_expires_at: datetime | None`；仅候选正常携带，其他状态为 `NULL`。
- 回滚 `v7→v6` 只在没有任何 `CANDIDATE` 行时允许；否则拒绝，避免丢失仍然有效的候选 TTL。

### 候选审计与拒绝正文

- 新增平台无关的 `MemoryOperation` 值对象；`MemoryStore.update(..., operation=...)` 在同一事务中写入 `memory_operations`。
- 确认：`CANDIDATE → ACTIVE` + `CANDIDATE_CONFIRM`，操作者为 `USER`，metadata 写 `from_status/to_status/memory_type/source_type/result=SUCCESS`，不含正文。
- 过期：`CANDIDATE → ARCHIVED` + `CANDIDATE_EXPIRE`，操作者为 `SYSTEM`，metadata 写 `candidate_expires_at`；正文保留。
- 拒绝：`CANDIDATE → REJECTED` + `CANDIDATE_REJECT`。`rejected_keep_body=false`（默认）时，在同一事务内物理删除该记忆的 revisions/sources/tags/relations 与 memories 行，只保留不含正文的 operation 审计；`rejected_keep_body=true` 时保留 `REJECTED` 行与正文。
- 拒绝后同内容可以重新成为新候选：唯一索引只覆盖 `ACTIVE/CANDIDATE`，拒绝路径不占用去重键。

### 只读管理 API

- 通过 `Context.register_web_api` 注册，路由以插件名开头：`/astrbot_plugin_weave_memory/v1/...`；宿主暴露为 `/api/v1/plugins/extensions/...`（旧宿主 `/api/plug/...`）。
- 端点全部只读：`overview`、`candidates`、`memories`、`memories/<id>`、`memories/<id>/history`、`groups`、`retrieval/debug`（POST 只做只读调试）、`settings`、`maintenance/status`。
- 鉴权：
  - 所有端点要求 dashboard 登录用户名存在；
  - 配置 `api_admin_usernames` 非空时，用户名必须在白名单；
  - 群作用域端点要求该群 `is_enabled=1` 且 `group_memory=GRANTED`；
  - 个人 scope 经 API 一律 `AuthorizationDenied`；Overview 只返回聚合计数；
  - 检索调试必须显式指定群 scope，不更新访问时间、不写检索诊断、不返回正文。
- 管理 API 不提供写端点；候选确认/拒绝、群开关、个人 opt-out 仍走命令或 dashboard 原生配置页。

### 配置

- `candidate_ttl_days`：默认 7，正整数；创建候选时写入 `candidate_expires_at`。
- `rejected_keep_body`：默认 false。
- `api_admin_usernames`：默认空列表；为空表示任何 dashboard 登录用户可读实例级端点。

## 后果

- v7 迁移与回填可测试；旧库升级后既有候选获得默认 7 天 TTL。
- 拒绝默认不可恢复正文，符合 LIFECYCLE「默认不保留可恢复副本」；需要审计正文的部署可显式开启。
- 管理 API 不能替代 WebUI；V2.1 复用同一套只读接口，写操作另行设计。
- 关闭管理 API 只影响 HTTP 入口，候选与命令路径不变。
