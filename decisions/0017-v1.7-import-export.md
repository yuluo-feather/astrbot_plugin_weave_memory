# ADR-0017：V1.7 导入导出（schema v8）

状态：Accepted（V1.7 实现契约）
日期：2026-11-23

## 背景

V1.2 只有服务层导出（`weave-memory-export-v1`），没有稳定幂等字段、没有导入、也没有管理 API 入口。V1.7 计划书要求：

- 导出 JSON 带 `export_id` / `source_platform` / `source_memory_id` / `source_revision` / `exported_at` / `schema_version`；
- 导入只创建新记忆，走验证/去重/冲突/作用域/consent，不绕过生命周期；
- 幂等四元组写入 `memory_sources.evidence_ref`，新增 `import_jobs`（schema v8）；
- 导入/导出按调用者作用域与 consent，不导出他人 Personal；
- 群导入/导出需要管理员，且群 `is_enabled=1` + `group_memory=GRANTED`。

ADR-0014 已冻结 schema v8；V1.6 的管理 API 是只读的。

## 决策

### Schema v8

- 迁移 `008_import_jobs.sql`：
  - 新建 `import_jobs`：`id`、`scope_id`、`subject_id`、`file_sha256`、`dataset_version`、`status`（`PENDING` / `RUNNING` / `DONE` / `FAILED` / `SKIPPED`）、`cursor`（已处理条目数）、`created_memory_ids_json`、`last_error`、`created_at`、`updated_at`；
  - 为 `memory_sources.evidence_ref` 建索引，支撑 IMPORTED 幂等查重。
- `scope_id` / `subject_id` 是任务归属，用于续跑与回滚时强制同一作用域；计划书的字段表未列出，但缺少它会让任务可被跨作用域续跑。
- 回滚 `v8→v7` 只在 `import_jobs` 为空时允许；不删除任何记忆。旧版本回滚链逐级先回 v8→v7。
- 迁移前自动备份沿用现有机制。

### 导出格式 v2

- `schema_version = "weave-memory-export-v2"`，取代 v1 的 `format` 字段。
- 文件级字段：`schema_version`、`export_id`、`source_platform`、`exported_at`、`scope`（仅提示，导入端忽略其 ID）、`memories`。
- 条目级字段：`source_memory_id`、`source_revision`、`memory_type`、`status`、`content`、`source_type`、`created_at`、`updated_at`、`valid_from`、`valid_until`、`metadata`、`exported_at`、`schema_version`。
- 幂等四元组 `(source_platform, export_id, source_memory_id, source_revision)`：前两项来自文件级，后两项来自条目级。
- 状态过滤：默认只导出 `ACTIVE`；`all` 额外导出 `ARCHIVED` / `EXPIRED` / `SUPERSEDED` 的元数据，`content=null`。不导出 `DELETED`，不导出 `CANDIDATE`。
- 导出不含内部 `creation_seq` / ledger `seq` / `scope_id` / `subject_id` 的权威值。

### 导入

- 只接受 `weave-memory-export-v2` JSON；Markdown 不导入。
- 文件级先校验，失败整份拒绝；条目级失败逐条记录，不中断整份导入。
- 文件中的 `scope` / `scope_id` / `subject_id` 只用于比较作用域类型：目标 Personal 只接受 Personal 文件，目标 Group 只接受 Group 文件；写入作用域始终由调用者解析。
- 只走 `WriteCoordinator`；只创建新记忆，不更新已有记忆；新 `memory_id` 由目标库生成。
- 幂等：先按 `source_type=IMPORTED` + 规范化 `evidence_ref` JSON 精确查重，命中即跳过；再按内容查重，已有 ACTIVE 同内容记忆时跳过；同内容 CANDIDATE 或唯一键冲突记为 conflict 并跳过，不自动确认候选。
- `ACTIVE` 条目导入为 `ACTIVE`（`SourceType.IMPORTED`、`OperatorType.USER`）；其余状态（`ARCHIVED` / `EXPIRED` / `SUPERSEDED` / `REJECTED` / `DELETED`）只写 `IMPORT_METADATA` 审计，不写正文；`CANDIDATE` 条目拒绝。
- `import_jobs` 记录 `file_sha256`、`dataset_version`、`cursor`、`created_memory_ids`；同一作用域同一文件的 `PENDING`/`RUNNING` 任务按 cursor 续跑，`DONE` 直接返回幂等摘要，`FAILED` 视为不可续跑、重新导入新建任务。
- dry-run 不写记忆、不写任务，只返回逐条预判。
- 回滚按 `created_memory_ids` 逐条走 `LifecycleService.delete_memory`，任务置 `FAILED`，不依赖完整备份。

### 入口与鉴权

- 个人：`/织忆 导入 [dry-run]`（消息附 JSON 文件）、`/织忆 导入 回滚 <job_id>`；`/织忆 导出 [json|md] [all]`。
- 群：`/织忆 群导入 [dry-run]`、`/织忆 群导出 [json|md] [all]`；要求群管理员、群 enabled、`group_memory=GRANTED`。
- 管理 API：`GET /v1/export`、`POST /v1/import`，只支持群作用域。两者都要求 `api_admin_usernames` 非空且 dashboard 用户名在白名单（fail-closed），群 enabled + GRANTED；个人 scope 一律拒绝。
- 这是 V1.6「管理 API 全只读」的受控例外：写端点仅群作用域、仅显式管理员白名单，个人写入仍只能走命令/Agent 工具。

### 配置

- 本版不新增配置项；导入上限为常量：文件 ≤ 5 MiB、条目 ≤ 5000。

## 后果

- v1 导出文件不含幂等四元组，按计划书要求拒绝导入；重新导出为 v2 后可用。
- 导入是低频操作，逐条更新 job 增加写放大，换取可断点续跑与可回滚。
- 管理 API 出现唯一写端点后，鉴权比只读端点更严格（白名单为空即拒绝），避免 dashboard 任意登录用户写入群记忆。
- 关闭导入导出不影响 V1.6 读取、检索与注入。
