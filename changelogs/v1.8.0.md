# 织忆 V1.8「归档」

> 对应计划书 V1.8 与 ADR-0018；备份不含账本，恢复按账本排除删除/撤销内容。

## ✨ 新增

- ledger-first 删除与授权：`/织忆 删除`、`/织忆 清空`、授权撤销、群销毁与附件删除先把权威意图写入独立账本 `memory_ledger.sqlite3`，再改主库；账本只追加、编号全局连续，可跨分段重放。
- 恢复旧备份时，已删除、已清空、已撤销授权、已群销毁、已删除附件的内容不会被复活。
- `/织忆 备份` 创建实例级主库快照，`/织忆 备份 列表` 查看；备份目录含 `main.sqlite3`、`sidecar.json`、脱敏 `config.json`、`README.txt`，不含账本。
- 默认保留最近 5 份、30 天，且不删除最新一份（`backup_keep_last` / `backup_retention_days`）。
- 备份在写租约内完成，带 sha256 与分表行数校验；产物为单文件快照，无 `-wal`/`-shm` 残留。
- `/织忆 恢复 <备份ID> [merge|revert|disaster-rebuild] 确认`，默认 `merge`；不带「确认」为 dry-run，先列出将复活/不会复活的清单。
- 恢复前自动创建快照并写 `restore_journal.json`；中途崩溃可在下次启动时重做，journal 损坏则拒绝继续（fail closed）。
- `disaster-rebuild` 用于空库重建：导入后轮换到新谱系，灾后新建记忆从头编号，不与旧谱系重号。
- `POST /v1/maintenance/backup|restore|reindex`：要求非空 `api_admin_usernames` 白名单且用户名命中，并要求 `confirm=true`；白名单为空时一律拒绝（fail closed）。
- schema v9：记忆新增谱系与创建序号，清空按「作用域 + 谱系 + 序号上界」精确排除；升级前自动生成迁移备份。
- 新增 `ledger_first_enabled`、`ledger_rotate_events`、`backup_keep_last`、`backup_retention_days`。

## 🔄 变更

- 删除/清空/授权撤销/群销毁改为「先落账本意图、再改主库」；关闭 `ledger_first_enabled` 可回到 V1.7 删除语义，备份/恢复同时禁用，schema v9 的谱系与序号分配保留。
- 恢复 dry-run 显示 `total` / `will_revive` / `will_not_revive`；实际恢复报告 `excluded_count`，表示按账本排除的备份行数。
- `group_max_memories=0` 现在真正关闭群记忆注入；schema 补说明。
- 群状态标注「启用时快照」，实际命令权限按当前平台角色实时解析。
- 提取任务失败改为任务内有限重试（上限 `extraction_max_retries`），不再留下无法再次调度的 `PENDING`；重启时清理残留 `PENDING`。
- 同一作用域、同一文件的并发导入返回 `Conflict`；串行调用仍可按 `cursor` 断点续跑。
- 候选通知统一为纯文本消息。
- 备份目标库统一 checkpoint 并切换 `journal_mode=DELETE`，备份目录只保留 `main.sqlite3`。

## 🔧 修复

- 恢复后重建 FTS：恢复事务内写入非空 dirty 哨兵；若 FTS 重建失败，索引保持 unhealthy，直到启动 journal 重做、启动恢复或手动 reindex 成功，避免用陈旧索引检索新主表。
- 恢复报告的 `excluded_count` 改为统计被账本排除的备份行，dry-run 与实际结果不再误导。
- 提取任务失败不再产生永久 `PENDING`；重启恢复同时清理 RUNNING 与 PENDING 残余。
- 同一文件并发导入会互相覆盖 `created_memory_ids`、可能导致回滚漏删；现串行化并拒绝并发。
- 命令错误文案：`ServiceClosed`、`InvalidTransition` 等不再向用户显示英文类名，改为中文提示。
- `memory_help` / 群帮助同时检查插件就绪状态，未就绪时给出提示而非异常。
- 账本 pending 重放失败时，日志记录失败事件 ID（最多 10 个），便于排查。
